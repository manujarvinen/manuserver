MANUSERVER

What it is

A server — in a virtual machine, or on a real computer as a home server — for serving a website with a Postgres database.

The website it serves is tastehopping: an anonymous place for the YouTube videos other people found worth keeping, and for voting on them. There are no emails, no passwords and no profiles — joining is one button, and the server hands you a made-up name and one long key that is the account.

One install gets all of it. nginx, PHP, Postgres and the tunnel software go on during the install, and the database sets itself up on first boot. Nothing is left for you to configure afterwards except the one thing that needs a secret: putting it on the public internet.

You need Arch Linux to build this .iso file — in your computer, or in a virtual machine. Building an .iso requires quite a few packages to be installed. You may want to do this in a virtual machine if you want to keep your Arch install minimal.

The .iso is x86_64 — for ordinary Intel and AMD computers. It will not run on ARM machines such as a Raspberry Pi or an Apple Silicon Mac. A virtual machine on them does not help either: those can only run the same processor type as the computer they are on. It can be emulated on them, which works but is very slow.

How to use

About 15 GB of free space is needed. Nothing else has to be installed first — the build script installs what it needs.

  1. Make the bootable .iso file, a minimal custom Arch Linux server, by running the script that comes with it. Usually 5–20 minutes, depending on your machine and connection. 
    git clone https://github.com/manujarvinen/manuserver.git
cd manuserver
./manuserver.sh build_iso

    If it says it added you to the kvm group, log out and back in before the next step. Otherwise the virtual machine runs without hardware acceleration, and the install takes an hour instead of a few minutes.

  2. With the .iso file, install the server. It has no graphical interface — terminal only.

    The following line, run from your local Arch Linux, will create a fresh virtual machine and install manuserver into it. 

    ./manuserver.sh vm_install

    Or write the .iso to a USB stick and install it onto a real computer.

  3. The installer asks only four things — network, username, password, and which disk to use — and sets up everything else on its own. It wipes the whole disk.
  4. When the install is finished, press enter. The virtual machine window closes on its own. It then offers to delete the .iso, put a manuserver command on your PATH, and delete the clone — leaving you with a server and one command that works from any folder.

    The virtual machine itself lives in ~/.local/share/manuserver, never in the clone, so deleting the clone cannot take it with it. Only installing again needs the clone back, because only that needs an .iso.

  5. Start the server: 
    manuserver

    Use the same username you gave the installer when you connect to it later.

  6. Open localhost:8080. The website is there, with its database already built. Press join and save the key it gives you — it is shown once and the server keeps only a scrambled copy, so it cannot show it to you again.

Running it

The cloned GitHub repository paradoxically includes the making of the server that clones the exact same repository onto itself — and that clone is what sets the server up, at the end of every install. It is a multi-purpose repository. 

manuserver               start it
manuserver vm_stop       shut it down
manuserver vm_status     is it running?
manuserver ssh mj        open a terminal on it
manuserver tunnel        put it on the public internet
manuserver backup mj     save the database to a file

Replace mj with the username you gave the installer. Leave it out and it uses your own computer's username, which is only right if the two match.

No window opens. manuserver starts the virtual machine in the background, from your own computer's terminal — the way a server runs. You control manuserver through ssh.

When you connect, it asks for a password: 

mj@localhost's password:

That is the password you chose during the manuserver install — not the password of your own computer.

Putting it on the internet

A tunnel publishes the server without touching your router: it dials out to Cloudflare, and visitors are passed back down that connection. Free, and the software is already installed and switched off, waiting for a token.

First, in a browser:

  1. Free Cloudflare account → Add a site → your domain, free plan.
  2. It gives you two nameservers. Change them at your registrar and wait for Active — minutes to a day, and the only slow part. Check the DNS records Cloudflare copied first, or an existing site and email will break.
  3. Zero Trust → Networks → Tunnels → Create a tunnel. Choose Cloudflared, name it manuserver, save.
  4. Copy the long string starting eyJhIjoi out of the command it shows. That is the token. Treat it like a password.
  5. On the same tunnel add a Public Hostname: your subdomain, type HTTP, URL localhost:80.

Then turn it on:

manuserver tunnel        virtual machine
sudo manuserver-tunnel             real server, over ssh

Paste the token at the prompt — nothing appears as you paste. It says within a few seconds whether the tunnel came up. Afterwards tunnel status and tunnel off do what they say; off deletes the token.

Only the one hostname and port you named are reachable. SSH and everything else on the machine stay invisible from outside.

Leaving it running

Locking your computer is fine — that only blanks the screen. The server keeps running, and so does everything connected to it.

The virtual machine is not tied to the terminal you started it from. You can close that terminal, or even log out, and it keeps going. Any other terminal of yours can check on it with status — including one opened over ssh.

Of yours meaning logged in as the same user. Someone else using the same computer cannot see or control it, and status would tell them it is not running.

What does stop it:

  • your computer going to sleep, suspending or hibernating
  • shutting down or restarting your computer
  • manuserver vm_stop

Most desktops lock the screen and then suspend a few minutes later. If you want the server reachable while you are away, turn automatic suspend off. After a shutdown it does not come back on its own — start it again.

manuserver itself never sleeps. It has no desktop and nothing set to power down when idle. If you watch it in a window the screen may go blank after ten minutes or so; that is only the display, and a keypress brings it back.

Security

A small personal server, not a bank — but most of this cost nothing to do properly. What it does not protect you from is at the end.

  • Root is locked, so everything goes through sudo: one account, one password, one audit trail. Your password is never written to a file, not even a temporary one — it is piped straight into the command that hashes it, memory-hard, in /etc/shadow.
  • The virtual machine is bound to your own computer, so neither the site nor SSH is visible to the rest of your network unless you ask for it. SSH also drops to three tries per connection, twenty seconds to use them, and no root login at all.
  • There is no database password, so there is none to leak. Postgres works out who is connecting from which system user opened the local socket, and accepts nothing from the network.
  • Only one file is reachable. The program and its queries live above the published folder, where no address reaches them. Values go to Postgres separately from the query, so a form cannot rewrite it.
  • Everything typed is escaped before it is shown again, every button that changes something proves the click came from this site, uploads are off, and errors go to the log rather than to the visitor.
  • Nothing says who anyone is. No email, no name, and only a scrambled form of your key is stored — a stolen database logs nobody in.
  • No access log, no third parties. No fonts from Google, no analytics, no CDN. The only outbound call is to YouTube, to ask what a saved video is called.

What it does not protect you from

  • Anyone holding a key is that account. No second factor, no recovery — the price of storing nothing about you.
  • Cloudflare can see the traffic. Their tunnel, their certificate; they sit in the middle.
  • A real home server is on your network, and its SSH takes a password — worth replacing with a key, which is two commands. In a virtual machine this does not apply.
  • The disk is not encrypted. Whoever holds the machine can read the database.
  • Nobody moderates. Posts vanish once enough separate accounts report them. That is the whole policy.
